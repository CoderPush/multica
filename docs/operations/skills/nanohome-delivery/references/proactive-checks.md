# Proactive checks

On the first eligible existing coordination cycle after 09:00 Asia/Ho_Chi_Minh, use available capacity for one read-only storefront area: search, navigation, images/gallery, catalog PDFs, mobile layout or VI/EN consistency. Bound worker discovery to 15 minutes/day. Record local date, area, URLs/viewports/locales, evidence and next area in NANO-2 to prevent repetition. If incidents/releases occupy capacity, defer to a later ordinary cycle, not another schedule.

Reproduce expected/actual behavior and check duplicates before filing a defect. Reuse a relevant issue; never create scan-only tickets. No orders, forms, uploads or production-data changes during discovery. Report unavailable browser capability as missing coverage. Prefer completing fixes over collecting tickets.

In the first Monday reconciliation after 09:00 local time, compare the previous seven days: verified closures/shipped changes, reopened defects, oldest actionable work, confirmed new defects and decisions still blocked. Separate completed scoped subtasks from shipped/live-verified outcomes. Mark missing history unknown; never manufacture metrics or split tickets to inflate counts.

Also sample delivery efficiency: duplicate executor runs, coordination-only runs, review issues per PR, missing next owners and recorded usage per completed delivery. Shorter prompts and fewer scheduled runs are not proof of token/cost savings. Use actual before/after evidence and report model/runtime attribution limitations.
