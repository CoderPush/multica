# Release boundaries

- Reconcile current GitHub state before acting. Historical instructions about an already-merged PR are not a new merge task; its merge does not authorize downstream migration or cutover.
- Preserve explicit holds on business behavior, price/stock semantics, checkout/cohort expansion, migrations/production data, permissions, spending, secrets/access grants, destructive work, DNS/source protection and unrelated projects. Gateway approval is not downstream storefront or asset-provider approval.
- Routine release uses current repository rules, exact-head independent review, required checks/signoff and required merge method. Never bypass checks, push main directly or force-push. If the head changes, refresh affected checks and review.
- For Medusa, push the branch and open a non-draft PR before `corepack pnpm ci:local`. Rerun after each push or PR title/body edit; never publish signoff directly. Confirm signoff matches the current PR head before merge. Read current AGENTS.md for any subsequent changes.
- A safe frontend-only change does not inherit an unrelated migration/upload prerequisite. Assess the actual dependency; do not erase a real release gate to accelerate work.
- Do not claim NANO-3/web#198 or NANO-7 complete without full applicable image/storefront acceptance. Read current evidence rather than perpetuating old reservations or DNS blockers.
- Checkout verification follows repository authorization: only the existing user-supplied low-value COD test cart/details, clearly marked as a test, verified in Medusa Admin and promptly cancelled. Reconcile an uncertain submission before retrying. No payment capture, fulfillment, cohort expansion or manual stock changes. If required details are unavailable, name that missing prerequisite rather than inventing them. Daily discovery never creates test orders.
- For a genuine exception, finish accessible preparation and provide exact scope/head, evidence, recommendation, rollback, owner and next action to Harley through Mika. Hoang owns design intent; Ian supplies MISA/data/IT rules. Never infer production authority from workspace access or acquire credentials to bypass a missing capability.
- Distinguish implemented, reviewed, merged, deployed and live-verified. Deployment health alone is not affected-flow acceptance. Independent review automation failure is not itself a code defect; assess concrete findings and preserve required gates.
