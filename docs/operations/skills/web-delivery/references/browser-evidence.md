# Browser evidence

Prefer browser evidence generated by the repository Regression Checks workflow when available. Keep the full pnpm check gate; a successful current-head CI run can satisfy it without repeating a full build on Hogan. Verify the current PR head, repository, workflow path .github/workflows/regression-checks.yml, run ID, attempt and conclusion through GitHub before downloading browser-evidence-<run-id>-<attempt>. Inspect workflow/tooling changes. The manifest is PR-controlled evidence, not an attestation. Cross-check its checkout SHA, PR head and tested base; pull_request CI tests a synthetic merge, while Vercel preview tests the PR head. Recheck intervening base changes.

Open and inspect the actual desktop/mobile images, not just the manifest. Default CI routes cover home, AWS announcement, AWS services and contact only. Obtain explicit evidence for every other affected route; do not claim omitted routes were reviewed. Expired, missing, partial, failed or stale evidence is not a pass. Operator-captured preview screenshots are acceptable when attributed and bound to a release SHA verified before/after capture. Never claim you ran a browser when you only reviewed supplied images. Save downloaded images under locally ignored .screenshots and link the exact GitHub run/artifact or attach actual files to the Multica evidence comment. No browser evidence path relaxes code review, human gates, head-matching merge or production verification.

A runtime failure is not permission to install browsers or alter host services. Report it separately and use authorized CI evidence when sufficient.
